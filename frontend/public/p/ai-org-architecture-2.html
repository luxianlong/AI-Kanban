侦查为什么是工作流,不是一个 agent

单 agent 会漏检索模态,而且无法自我证伪。上一轮对抗核查提出 123 处更正, 拦下多个致命错误 —— 最典型的是「某人当面骂他是骗子」流传极广,唯一信源竟是被指控者本人的回忆。 没有核查,这句一定会被写进稿子。

三道闸

  1. 引语闸门 —— 成稿里每段引号内的文字,必须是 dossier/raw/ 下某个原件的子串
  2. 红线 —— markdown 记号 / 讨要式钩子 / 器官词 / 字数
  3. 未落盘断言 —— 引号找不到原件时,给出最接近的原件片段供人工判断

外文素材:译文不可能是原文的子串,所以引用外文原话时必须同时出现原文和译文, 格式 「原文」(译:译文)。

闸门拦住过真事。某篇成稿把「PR在我们这儿就是跳动的心脏，时不时就得蹦跶一下， 不蹦就死了」中间那句删掉了,却没有给省略号 —— 等于把压缩过的话当逐字引语发。 同一句在另一篇里是完整的,所以那篇过了闸、这篇没过。差别就是一道确定性检查。

卷宗即记忆

引用了谁的原件,那份原件就该躺在自己的 raw/ 里。否则闸门连比对都做不了 —— 真出过一次:某个 run 的原件躺在隔壁 run 的卷宗里,闸门直接判「无法执行」,稿子卡了一天。

两条交付路径

路径怎么走
知乎人工。HTML 出来后复制粘贴
公开页publish_page.py → /p/<slug>.html

知乎那条曾经想自动化:Draft.js 只认真实输入事件,AppleScript 要辅助功能权限且会掉, CDP 要算截图坐标系,插图还得绕 Chrome 的 Private Network Access。三条路各有各的坑, 单次成功率低 —— 所以砍掉了,改出 HTML。

发布是单向的。公开页接口匿名写、站长才能删 —— 发出去自己撤不回来。 所以 publish_page.py 默认强制过闸,不过不发。
