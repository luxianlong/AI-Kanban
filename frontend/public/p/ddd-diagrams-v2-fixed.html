图版一 · 实线=交接物(文件名即契约),虚线=依赖共享内核。第一版里侦查那条是「未共享」,当天已修好

三件事值得单独说,因为它们和「标准 DDD 图」长得不一样,而且都是实测出来的:

上下文之间零代码耦合。全项目 grep 跨上下文 import,结果是 0 —— 每个上下文只 import 自己和共享内核。集成**全部通过文件**:hot.json、 candidates.json、raw/、facts.jsonl、answer.md。 这不是缺陷,是这个系统的真实形态:交接物即契约,而且交接物在磁盘上,冷启动后还在。

防腐层是 SourceAdapter。微博、知乎、谷歌各有各的字段, 适配器把它们归一成 Item,外部模型进不了内部。端口在共享内核,实现在各上下文的 infrastructure/ —— 端口在内、适配器在外。

第一版的发现 · 已修好

第一版画出来时,侦查上下文 import 共享内核的次数是 0。但它恰恰是 facts.jsonl 的生产者 —— 而那份文件是整条分级红线的载体。它用裸 dict 写事实, 不走 Fact 类型,于是词表漂移没有任何拦截点,而且已经真的发生过: 提示词写「倒推的数一律标【推算】」,内核不认识,两条事实的分级静默变成 None。

当天修完:harvest_flow 落盘前经 Fact 校验,认不出的词带流名、路名、 原文报到 stderr 并以 exit 3 结束。实测重采 17 条真实流,facts 逐字一致、判决不变。 现在侦查 import 共享内核 3 处(harvest_flow、carriers、carrier_review), 图一里那条虚线因此改成了正常的共享内核依赖。

但拦截点还在少数派那侧。实测 facts 共 132 个文件 / 3,799 行, harvest_flow 只产其中 31 个 / 2,109 行;另外 97 个是 agent 按 investigate.js 用 Bash 直写的, 那条路上仍然没有守门人 —— 而历史上唯一真漂过的那 2 条【推算】,恰恰就在直写的文件里。

图版二 · 位置是判断,不是测量;行数是实测。侦查从第一版的「0 行领域层」变成了领域层最大的上下文

差异化这一轴的判据是:换成任何一个通用工具,这件事会不会立刻塌掉。 引语闸门会——没有别的工具会拿成稿里每一处引号去和原件做子串比对。 发布会渲染 HTML 的东西满地都是,所以交付在最下面。

第一版的发现 · 已补上

第一版:侦查是差异化最高的子域,却有 0 行领域层。 整个系统的教义是「质量来自一手材料的独占性」,而实现这条教义的载体回溯清单十二条, 一条都不在代码里 —— 全住在技能文档和提示词里。同样的病在选题上犯过: 规则不在代码里就会破例,14 次选题破例 5 次、5 次颗粒无收,写进 scout.py 才止住。

当天补上 domain/carriers.py:把十二条里可判定的 8 条写成代码, 判不了的 4 条明确标成「代码判不了」,永远不升成「通过」—— 硬把判不了的写成通过,比不写更糟,那会制造「已经翻完了」的假象。不打分、不设阈值。 侦查的领域层因此从 0 变成 527 行,现在是五个上下文里最大的一个。

但它目前还没有接口层、没有调用方。 在接进侦查收工步骤之前,不要对外说「规则已经进代码」—— 现在只是从技能文档搬进了一个没人跑的模块。

这张图也解释了为什么侦查和交付整体落在基础设施层是诚实的、但不是终点: 交付本来就该是通用域,永远不长领域层没关系;侦查不长,是欠账。

单个边界内部的模型:卷宗聚合、它的不变式,以及分级红线的唯一定义处。

图版三 · 每个类的第一行是构造型;Draft 与四条 Spec 属质量上下文,不在本图

这个聚合只有一条真正的不变式,但它是整个系统里最重要的一行代码:

不变式在哪为什么是它
【网】【传】【假】不得进成稿FactGrade.writable 红线只在这里定义一次。规格只做判断,不重新解释分级。
禁写清单 = 有原话且不可引Dossier.forbidden() 判据是 quotable(分级+禁写双条件),不是 usable_in_draft 单条。
【实·单方】只能写「他说」needs_attribution 核实的是「他说了」,不是「这是真的」。

为什么没有仓储层。持久化就是文件系统,runs/<id>/ 本身就是聚合边界。 加一层 Repository 只会让「卷宗即记忆」这件事更难验证 —— 冷启动后能不能靠目录本身恢复上下文, 是这个系统的硬指标。

为什么没有事件总线。events 是一条 append-only JSONL,没有订阅者、没有重放。 它存在的唯一理由:过规格和发布这两个时刻以前只 print 不落盘, 导致「哪些成稿过了规格却没发」根本答不出来。

四、这一天改了什么,还欠什么

三张图画完之后,当天照着它们改了三轮。图里指出来的两条欠账都动了, 而每一轮的对抗核查又揪出新的 —— 下面按「已修 / 仍欠」分开列,不混在一起。

已修怎么验的
分级与推导方式分家 推算 被当分级词写进卷宗,而它根本不是可信度等级。 Fact 新增 derived,parse() 认得推导词并给出说得清的报错。
侦查经内核落盘 重采 17 条真实流,facts 逐字一致;quotable / forbidden 判决不变。
核心域补上领域层 12 个真实卷宗跑通,可判定的 8 条查证据、判不了的 4 条如实标注。
三处静默失败 journal 坏行会吞掉整个 agent、缺 grade 静默放行、坏 jsonl 静默跳过 —— 全部改成要吵。
产线不问动机 实测 167 条 why_matters 零条讲动机。新增 motive 路与 cui_bono / why_they_did_it 字段,fast 模式也不裁这一路。
仍欠为什么要紧
carriers.py 零调用方 527 行没有接口层、没接进收工步骤。规则只是从文档搬进了一个没人跑的模块 —— 动因(规则不在代码里就会破例)并没有被解决。
拦截点在少数派那侧 facts 共 132 文件 / 3,799 行,harvest_flow 只产 31 文件; 另外 97 个是 agent 直写的,那条路上没有守门人。
选题门槛停用但仍在算 这不是缺陷,是可逆的策略开关。判定仍写在 ok / reject 里供人工看。

一句方法上的话。这三张图最大的用处不是画得好看, 是它们把「侦查有 0 行领域层」这种事变成了一眼能看见的东西。 在画之前,那 391 行纯基础设施看起来完全正常。
