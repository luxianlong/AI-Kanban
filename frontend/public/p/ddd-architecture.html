1. 领域与子域划分

业务领域:热点事件写作 —— 从全网发现正在发酵的事件,回溯到一手载体, 产出可核验的文章并发布。竞争力不在文笔,在一手材料的独占性,这决定了子域怎么分。

子域类型为什么这么定
侦查 Investigation核心域 独占材料只能在这里产生。二手转述层里没有护城河
质量闸门 Quality Gate核心域 把没核实的话安在真人头上是业务性风险,不是技术性风险。它是可信度的唯一强制点
选题 Topic Selection支撑域 规则明确、可编码,但绑定平台;换平台要重写
成稿 Authoring支撑域 由 LLM 承担,不建模;约束由闸门在出口施加
信源发现 Source Discovery通用域 就是查新闻。用现成的 Google News RSS,不自建
交付发布 Delivery通用域 渲染 + HTTP POST。唯一特殊之处是不可逆(见 §5)

2. 限界上下文与集成模式

关系模式契约
外部平台 → 选题 / 信源发现Anticorruption Layer 把平台各异的指标翻译成内部模型。阈值不可跨平台复用(见 ADR-1)
选题 → 侦查Customer / Suppliercandidates.json,下游只取一个 index
侦查 ↔ 成稿Shared Kernelruns/<id>/dossier/ 的目录契约
成稿 → 质量闸门Conformist作者服从闸门,闸门不为作者让步
质量闸门 → 发布前置守卫publish_page.py 默认调用 gate,失败即拒发

3. 战术设计:聚合

Dossier 卷宗 聚合根

标识 = runs/<run-id>/ · 事务边界 = 该目录

成员类型字段(实际)
RawArtifact实体 url · file · http · content_type · fetched_at · note
EvidenceImage实体 file · source_url · what · why · captured_at
Fact值对象 claim · grade · when · verbatim · source_url · raw_file · why_matters · usable_in_draft
TimelineEntry值对象同一作者名下载体的时间戳序列
不变式 I-1:Fact.raw_file 必须指向本卷宗 raw/ 下的实体。跨卷宗引用会让闸门无法比对 —— 实际发生过一次, 某篇的原件躺在隔壁 run 里,闸门直接判「无法执行」。
不变式 I-2:grade ∈ {实, 实·单方, 网, 传}。 【网】【传】不得进入成稿;【实·单方】只能表述为「他说……」,不得表述为「事实是……」。

Candidate 候选题 聚合根

标识 = 平台侧问题 id · 工厂 = scout.py rank()

字段说明
id · title · visits · answers · follows · created · top1ACL 从知乎翻译而来
ok · reject[]判定结果与逐条驳回理由
kind围观 / 求助 / 中性 —— 句式决定阅读基数
index仅合格项获得,按 visits 降序
不变式 I-3:四条阈值全过才进 candidates 集合 —— len(id) ≥ 18 ∧ visits ≥ 50000 ∧ answers ≤ 50 ∧ top1 ≤ 1000。 下游只能提交 index,不能提交一道题:不合格项不在选项空间内。

PublishedPage 已发布页 聚合根

标识 = slug(不可变) · publish_page.py

不变式 I-4:创建即终态。接口匿名写、仅站长可删, 同名 slug 不覆盖而是退避为 -2 / -3。因此校验必须前置, 没有「发完再修」这条路径。

4. 规格模式:闸门的四条判定

gate.py 是合取式规格(Specification),四条全过才返回 0。 注意它比常被引用的「三道闸」多一条 —— usable_in_draft 禁写清单是独立判定, 不是引语闸门的一部分。

规格判定失败信息
QuoteSpec每处引号内文本必须是 raw/ 下某原件的规范化子串 给出最接近片段与相似度,便于人工判断
RedlineSpecmarkdown 记号 / HOOK_PAT 讨要式钩子 / ORGAN_WORDS / 300 ≤ n ≤ 4000 逐条列出命中位置
ForbiddenFactSpec任一 usable_in_draft=false 的事实,其 verbatim 不得出现在成稿 指出是哪一条
ExecutabilitySpecraw/ 为空而成稿有引述 → 失败而非跳过 「引语闸门无法执行」

第四条是防御性设计的关键:缺少证据时系统失败关闭(fail-closed),而不是静默放行。 外文素材同理 —— 译文不可能是原文的子串,所以必须原文与译文同时出现,由原文过校验。

5. 持久化与并发

关注点做法理由
仓储无仓储层。文件系统即持久化,runs/<id>/ 即聚合边界 卷宗要能被人直接检查;加一层抽象会让「clear 之后只读卷宗」难以验证
写入模型manifest 为 append-only JSONL近似事件日志,可追溯,不需要迁移
并发写每路 agent 写各自的 facts/<angle>.jsonl,成档时合并 曾并发追加同一文件导致损坏。分片 + 归并取代锁
图像采集强制串行,独占浏览器 Chrome 的活动标签是全局互斥量:并发开标签会让截图全白、点击打偏
跨上下文结果传递工作流产出必须落盘(harvest_flow.py) 返回值只活在一条任务通知里,上下文一清就没了

6. 架构决策记录

ADR-1:阈值不跨平台复用,每个上游一个 ACL

背景:知乎的四个指标源自其答案排序机制(浏览 / 回答数 / 首答赞数 / 问题 id 位数)。 微博热搜的量纲是热度值、榜位、在榜时长;X 是 post 数与榜位。

决策:每个上游平台一个适配器,阈值各自定义,不共享常量。

理由:「我还能不能排进去」这个概念只在知乎的答案排序下成立, 其他平台不存在对应物。强行复用等于把上游模型泄漏进核心域。

ADR-2:约束施加于出口,而非读模型

背景:防止虚构的常规做法是限制作者可见范围 —— 只给摘要,不给原件。

决策:成稿上下文对 raw/ 拥有完全读权限, 校验完全由出口处的闸门承担。

权衡:削减视野会同时削掉发现能力 —— 最有价值的观察产生于全部材料同处一个 上下文之时(例:「整张封面唯一被标红的是『请随意转发分享』」,任何抽取器都拿不到)。 代价是闸门必须足够严格且不可绕过。

ADR-3:取消角色分权,改由确定性工具承担

此前:四个 LLM 角色(总监 / 高级 / 初级 / 答题员),以 can_use_tool 白名单实现权限隔离。

现在:单一编排者 + 九个确定性脚本。2026-08-29 已删除角色管线。

理由:角色分权约束的是谁能调什么,而实际需要约束的是什么能通过。 14 次选题中有 5 次靠自觉破例、5 次全部零产出;把门槛移进代码后该类越界不再可能发生。

ADR-4:浏览器通道唯一化

背景:曾并存两条通道 —— osascript 驱动与 Claude in Chrome。

决策:2026-08-29 删除 osascript 驱动。传输层交给 agent, scout.py 退化为「吐 JS + 过阈值」的纯函数式工具。

理由:两条通道争抢同一活动标签(症状:输入不生效、JS 打到无关页面); 且 osascript 的 TCC 授权会被静默撤销,失效时不报错。 关键在于:改变传输方式的同时,I-3 不变式仍留在代码中。

字段与阈值取自 tools/*.py 与 runs/<id>/dossier/ 实际数据。 本页只描述结构,不含运营数据。
