值对象第一次说清了「我不是什么」。

Fact 现在有 11 个字段。同时 fact.py 里多了一个 _SIDECAR_KEYS —— 7 个故意不进实体的旁路键 (flow angle evidence url was downgrade_reason unverified)。 它们由采集脚本和侦查流写在同一行里,讲的是「这条事实从哪来」, 不是「这条事实是什么」。

两者相加得到 18 个已知键,就是 from_json 的警戒线: 键不在这 18 个里,就往 stderr 吵一声。吵完照样返回一条 Fact, 不拦人 —— 这是刻意的,拦下去只会让一次正常采集把整条流水线停住。
这道警报的第一次真实运行,当场响了一次。

   侦查侧 Schema 可能已经加了字段而内核没跟上,这些值会被丢掉。
grade_note 出现 1 次,在 runs/20260831-日本就职冰河期/dossier/facts.jsonl 第 59 行。 全仓搜 grade_note:investigate.js 里没有、 fact.py 里没有、技能文档里也没有 —— 是某个核查 agent 自己发明的键。 它的值是空字符串,所以那一次什么也没丢。

⚠️ 这一条现在复现不了了,原因见第五节。那份 facts.jsonl 在中间那 58 分钟里没了,而它从来没有进过任何一个提交, 所以恢复不回来。今天同一道警报对现存的 10 份卷宗、541 条事实跑,一次都没响(未知键:无)。 带动机字段的还剩 92 条 —— 拿上一版的 Fact(9 字段)读, 这 92 条照样一条都进不来。
顺带证实了 grade_note 是哪一步冒出来的。 日本卷宗的分路台账 dossier/facts/ 里 17 个文件、230 条事实 全部还在(它们进了提交),而这 230 条里 grade_note 出现 0 次。

也就是说:这个键不是取证那一步写的,是核查那一步合并时才出现的 —— 和「某个核查 agent 自己发明的键」这个判断吻合。同时这也说明合并版 不是分路文件的简单拼接:它带着核查阶段的更正,那些更正只存在于合并版里。
两侧模型现在对得上了 —— 一个方向上。

侦查侧 FINDINGS 的每条 finding 有 10 个字段, 全部在实体的 11 个字段里(Schema ⊆ 实体)。上一版不是这样: 那时 cui_bono / why_they_did_it 在 Schema 里、不在实体里。

反过来还差一个:实体多出来的那个字段是 derived(这个数是抄的还是算的), 而 derived 在 investigate.js 里出现 0 次 —— 侦查侧永远不会填它,它只能由 from_json 拿 DERIVATION_WORDS (推算 倒推 估算 推断 测算)去猜。而这 5 个词与 Schema 的 grade 枚举 交集为空 —— 枚举只允许那 5 个分级词。也就是说:内核留着一条兼容规则, 防的是一种现在的 Schema 已经不可能产出的写法。

为什么会这样,而且不是 bug。

这四道哨兵全都是一致性检查:它们问的是「同一个东西在两边说的是不是一样」。 而把两边一起删掉,是让两边一致的最省事办法 —— 空集等于空集,空集包含于空集,没有提示词就没有死承诺。

四道里没有任何一道问的是:「这些东西还在不在」。

这正好把第一节那条边的问题推到底。第五版说:LLM 那条边上没有编译器, 所以 Schema 加字段而实体不跟,不会报错。这一版说:连我们自己加的哨兵也只盯漂移,不盯存在。 一个删掉半边的改动会被抓住(两侧不一致),一个删掉两边的改动反而全绿。
恢复救回了 3522 个文件,还是丢了一个。

反做用的是 git revert 而不是 reset --force,所以历史没被改写, 树也确实回到了 d3a602e(git diff d3a602e HEAD = 0 行)。 但 git 只能还原它记得的东西。

runs/20260831-日本就职冰河期/dossier/facts.jsonl —— 那份 98 条的合并事实台账 —— 从来没有进过任何一个提交(git log --all -- 该路径,输出为空; #177 那个提交里,该 dossier/ 下进了库的是 BRIEF.md、GAPS.md、 facts/、images/、origin.json、raw/、timeline.json、txt/, 唯独没有它)。其余 10 份卷宗的合并台账 10/10 都在 git 里 —— 只有这一份漏了。

它是这个聚合最值钱的那一份文件:分路台账是取证阶段的原始产出, 而合并版带着核查阶段的全部更正 —— 上面那条 grade_note 只在合并版里、 分路的 230 条里一次都不出现,就是证据。分路文件还在,所以能重跑合并; 但重跑出来的不会是同一份,核查阶段的更正不在分路文件里。

一句话:「git 记得什么」这条边界,和「聚合需要什么」这条边界,不是同一条。 而这条边界,三张图里同样一根线都没画。
