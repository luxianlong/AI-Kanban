1选题:门槛写在代码里,不写在提示词里

contexts/selection/domain/zhihu.py 四道硬门槛:题目 ID ≥ 18 位、浏览 ≥ 5 万、回答数 ≤ 50、首答赞 ≤ 1000。不合格的题根本不会出现在候选表里。

为什么必须是代码:上一轮 14 次选题破例 5 次挑了短 ID 老题,5 次全部颗粒无收。

人判 选哪一个。而且 2026-08-29 起加了一步:调研完先发一个候选网页给人确认,拿到编号再往下走。理由很实在 —— 侦查一轮实测 70 分钟 / 12 个 agent / 81 份卷宗,确认成本一分钟,返工成本一小时。

2侦查:一个 agent 不够,因为它无法自我证伪

工作流并发多路检索,再跑一轮对抗核查。上一轮核查提出 123 处更正,其中最典型的一条:某句「当面骂他是骗子」流传极广,唯一信源是被指控者本人的回忆。没有核查这句一定会进稿子。

产出落进卷宗:BRIEF.md 简报、GAPS.md 补漏清单、facts.jsonl 分级台账、raw/ 原件、images/ 证据图。

事实分级是四档,不是真假两档

级别标准能否写进成稿
实权威源,且亲眼读过原文能
实·单方当事人自己说过这句话能,但只能写成「他说……」
网广泛流传,无权威源不能
传未证实传闻、单一匿名源不能

另有一组「推算词」(推算/倒推/估算/推断/测算)不是分级 —— 一个推算出来的数可以是实,也可以是传,推算与否和可信度是两根轴。这条是因为分级词漂过一次才写进 domain/fact.py 的。

2.5证据图:必须用眼睛看一遍

排版强调 —— 颜色、字号、标红 —— 任何抽取器都拿不到。上一篇最锋利的一句就是这么来的:「唯一标红的是请随意转发分享」。

土地那篇同样靠读图改了两处:国标那两张表是无文字层的扫描件,只能逐行读;读完才发现简报里那个比值用的基准是「多层Ⅰ类对高层Ⅱ类」,不写明基准读者会以为是拿平房比高楼。

2.7大纲:这一步是今天才加的

contexts/quality/domain/outline.py。四个栏目,每一个都是一次踩坑换来的:

栏目要求来历
论点一句话,只能一个#109「哪有一个文章三个结论」
对立面谁在说一个错的说法#110 被夸的两篇都这么开头
骨架每一节写明给读者什么新东西#111「不是炫耀数据扎实,是让读者有收获感」
落点读者带走什么,不许推给别处#110 落点拒答 62 篇里只有 1 篇

为什么值得加这一步,有账可算。土地那篇从 v1 改到 v6,六轮里只有一轮是因为事实错了,其余五轮全是结构问题:

轮次问题类型
v1→v2落点拒答、开头没有对立面结构
v2→v3没回答题目问的那个问题结构
v3→v4只摆数字不讲道理、不敢下判断结构
v4→v5口吻不对结构
v5→v6段落冗长、有干燥带结构

结构问题全都可以在动笔前问掉,而返工成本逐轮递增 —— 到 v5,一次重写要连带重建四张证据图的锚点和图注。

骨架那一栏最容易糊弄:写「第三节:讲容积率」不算数,要写「第三节:让读者知道那个数是下限不是上限」。一节说不出给读者什么新东西,这一节就不该存在。

还有一条,是八轮返工里三个超长段回溯出来的:一节只装一件事。装两件,写出来必然是一百多字。在段落层面切,是把一节硬塞进两段;在大纲层面拆,才是让它本来就是两节。

大纲写完会单独发一个网页,动笔之前给人看 —— 这篇的大纲长这样。

3外语初稿:先写德语,再译中文

最初定的是英文(#103),2026-08-30 换成德语(#113)。语言不写死在代码里,提在一张表里:

生效日文件语言
20260831answer-de.md德语
20260830answer-en.md英文

它治什么、不治什么,都量过。同一篇内容、同样 34 段:句数 66→74,p90 句长 54→46(降 15%)。但超 40 字的长句一条没少,最长那句还长了 3 个字 —— 它治的是中等偏长句子太多,治不了内容本身复杂,更治不了结构。

换德语的理由是假设,不是结论。换之前量过 6 篇英文初稿:一篇每千词 6.9 处比喻,其余 5 篇合计每千词 0.24 处。比喻集中在一篇里,不是英文写作的系统性毛病。所以德语这一版是个真实验,判胜负要攒够 6 篇再比,而且要同时看中位数和最大值。

引语闸门有一个它查不到的盲区,值得单独说。它能查引号里的字是不是真的,查不出引号外面那个框是不是编的。土地那篇差一点发出去一条假因果:「限高的理由被通稿删掉,十八个月后才露面」。七处引语全部逐字落盘,而错的是我给这些真引语套的因果 —— 那句话 2025-07-17 就由新华社侧记原文引出,离通稿只隔两天。这是靠去查它全网第一次出现在什么时候才拆掉的。

6polish:套话、比喻、节奏

比喻这条最能说明词表的宿命。它已经补了三轮,每一轮都是先犯了再补:

轮次漏掉的补了什么
#88三把尺子财经套话载体 12 个
#112旋钮、发动机、长出了牙、同一只手器物词 14 个 + 三种裸比喻句式
#115施工图、把方向拧回去、预期接不住再补 3 个

#112 那次第一版规则误伤了 3 篇,全是把真东西当成比喻:「我看着她那双手」(真的手)、「发条消息」(发+条量词)、「这部戏」(真的电影)。收紧后:该抓的 8 处全抓到、行号精确,62 篇历史稿误报 0。

抓不到比喻是漏,冤枉一篇好稿是错。提示型检查一旦开始误报就没人看了。

人判 词表永远落后于自己,交稿前还得自己读一遍 —— #115 那三处就是 polish 没报、自己扫出来的。

7编辑复审:查「值不值得读」

这一步和闸门是两件事。闸门八条全过、polish 零问题的稿子,照样可以又长又闷。#115 那版就是,读完的评价是「不是在炫耀数据有多扎实」。

两副镜片,各自开口第一句:

编辑「嫌它长」

这段删掉,读者会少知道什么?说不出来就删。

代码算:空转段、干燥带、四字重合的复述

编辑「嫌它闷」

读者读到这儿,凭什么还往下读?

代码算:第一个硬东西出现在第几段、段长 cv、超长段、结尾与开头的重合度

有意见就回大纲,不许在旧文上改。#119 那次我在旧文上切段落,切完再跑工具立刻顶出新的超长段,再切又顶一个 —— 病根不在段落,在骨架。三个超长段回溯到大纲,三个都是「一节扛了两件事」。在段落层面切,是把一节硬塞进两段;在大纲层面拆,才是让它本来就是两节。

实跑三轮,有两轮改了稿,有一轮改的是工具自己:

  • 一轮 抓到连着 4 段没有硬东西。合并、切分,共改 4 处。
  • 二轮 中段干燥带消失,工具立刻改报结尾。但结尾本来就不该有数字 —— 落点是给读者带走的判断,不是证据。这是指标该让路的地方。于是给检查加了结尾豁免,写进代码而不是靠人每次记得忽略 —— 记得忽略一次,下次就会顺手忽略真问题。
  • 三轮 只剩一处,看完决定不改:那是「容积率就是个除法」那一段,一个数字都没有,却正是上一轮要求补上的东西。工具把「解释」误读成了「空转」,照它删等于把上一轮的成果撤回去。这条已写进 CANNOT_JUDGE 并排第一。

结果:段数 52→54(切开两个超长段),节奏 cv 0.57→0.53,「嫌它闷」三条意见归零。

总这条流水线到底信什么

一 · 质量来自一手材料的独占性,不来自文笔

那篇全网独一份的稿子,靠的是「发帖 24 分钟后建了 GitHub 仓库」「自定义排版宏」「官网有个叫 Novel 的栏目」。而那个 GitHub 地址,就印在原文最后三行里。没人写,只因为没人读原文。

二 · 规则不是靠记的,是靠跑的

markdown 记号那条一个月犯了三次,每次都是闸门抓回来的。落进代码之前,全仓库 grep「落点」只有一处命中,「动机」零处 —— 这两条一直只活在提示词的散文里。

三 · 判不了的要明写出来,不许假装覆盖

每个领域模块末尾都有一份 CANNOT_JUDGE。比如:落点是否真的回答了开头、对立面是否真有人在说、主角是否是一个做了选择的主体(这条属选题不属成稿)、语气配不配这个身份 —— #116 那版的价值全在语气上,任何指标都量不到。

四 · 指标该让路的时候要写进代码

结尾豁免那一条。靠人每次记得忽略某个误报,等于训练自己无视这个工具。
