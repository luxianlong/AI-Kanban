发布接口验收记录

对 POST /api/pages 免鉴权上传通道做的一次端到端验证。本页自身就是被上传的那个文件。

通道可用 —— 本页能被你打开,就说明整条链路是通的

验收了什么

接口POST /api/pages
鉴权无(匿名写)
提交方式Content-Type: text/html + --data-binary
上传前 GET /api/pages[] —— 本页是第一张
公开入口直链 /p/<slug>.html + 文档墙 /docs.html

复现命令

curl -X POST 'http://www.youraikanban.com/api/pages?title=...&slug=...' \
  -H 'Content-Type: text/html' \
  --data-binary @page.html

返回体里的 url 就是公开地址;slug 重名会自动退避成 -2、-3,不会覆盖既有页面。

用之前要知道的三条边界

  • 必须单文件自包含 —— 内联 CSS/JS,图片走 data: URI。不支持传目录或附带资源。
  • 配额 —— 单页 ≤ 5 MB、总数 ≤ 200 张、同一来源每小时 ≤ 30 次,分别返回 413 / 409 / 429。
  • 发布匿名,下架不匿名 —— DELETE 在密码门后面。陌生人能发,但删不掉别人的页面;发布者自己也删不掉。
HTTPS 目前不可用。本次上传只能走明文 http:// —— 对 :443 握手直接 SSL_ERROR_SYSCALL。教程里写的 https://<域名>/p/<slug>.html 现在打不开,得把协议换成 http。匿名写接口跑在明文上,建议优先把隧道的证书补上。

沙箱是对的

这些页面由陌生人提供却跑在看板自己的域名下,服务端加了 Content-Security-Policy: sandbox 且不含 allow-same-origin —— 页面自己的脚本照常跑,但拿不到看板的 Cookie / localStorage,也没法冒充站长去调 /api。 这是这个设计里最关键的一道保险。
