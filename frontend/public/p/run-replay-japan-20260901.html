四拼完当场跑出来的四个毛病

毛病一 · 4 条事实的定级写成了日文汉字「実」

全部 4 条都在 verify.jsonl 里,claim 也全是日文 —— 核查 agent 在日文语境里顺手打了日文汉字。后果不是报错,是静默作废: 
FactGrade.parse("実")  →  None      (并往 stderr 吼一声)
Fact.from_json(grade="実").quotable  →  False
也就是说,这 4 条经过核查确认的事实,在内核眼里既没有分级、也不可引用。

为什么没人拦:侦查侧 Schema 的 grade 枚举里没有「実」 (全文搜 investigate.js,出现 0 次)。但 Schema 校验的是 agent 返回给工作流 的值,不是 agent 自己写进卷宗 的文件 —— facts/*.jsonl 是 agent 拿 Bash 徒手写的。枚举对这个文件没有约束力。
毛病二 · 196 次抓取里 63 次失败,没有任何地方汇总过

成功率 133/196 = 68%。失败分布:404 十五次、连不上十一次、403 三次、 另有 33 条 manifest 根本没记 HTTP 状态。

这些数字一直躺在 raw/_manifest.jsonl 里,格式良好、随时可读 —— 但从来没有任何一步去读它。「哪一路的取证其实什么都没抓到」这个问题, 现在没有任何人问。
毛病三 · 成稿的引号,只有 4 处能在事实台账里逐字对上

成稿里共 13 处 「」 片段,其中能在 facts/*.jsonl 的 verbatim 里逐字找到的只有 4 处。

逐条看完之后,这 13 处其实是三类,不能笼统说成「9 处没出处」:
· 六处是中文术语或强调(「扎实的成果」「地域青年支援站」),本来就不是逐字引用;
· 「これ、未達であったがために二年間延長した」在原件里逐字命中, 但不在任何 verbatim 里 —— 写手是直接从 raw/ 里摘的,绕过了事实台账;
· 「まるで『出口』…」那句同样在原件里命中。

只有一处站不住:「持ち回り開催」。原件里有「持ち回り」、有「開催」, 但没有「持ち回り開催」这个连写。它被当成原话打了引号,而那个连写不存在于任何原件。
毛病四 · 最值钱的那份产物,从来没进过仓库

dossier/facts.jsonl(合并版事实台账,98 条)从未进过任何一个提交, 所以 9-01 上午 runs/ 被清空时它一起没了,而 git revert 救不回 git 从来不认识的东西。其余 10 份卷宗的合并台账 10/10 都在仓库里,只有这一份漏了。

它为什么最值钱:分路台账 facts/ 是取证阶段的产出, 合并版带着核查阶段的全部更正。所以「这一轮核查到底改了什么」这个问题, 对这篇文章已经永久答不上来了。(此事已单独记在三张图第六版里。)

六要做成常设的,我建议只做一件

不建议一上来就建大盘。上面四个毛病里有三个,根子是同一件事: 这一轮的运行数据从来没有被收进卷宗 —— 它躺在会话目录里,会话一结束就没了。

项目里已经有那个采集器(contexts/investigation/harvest_flow.py), 它本来就是干这个的,只是这份卷宗上没人跑过它。所以第一件该做的不是写新东西, 而是让每一轮侦查结束时必跑一次采集,把 journal.jsonl 的成败摘要、 每路的事实数、抓取成功率一起写进 dossier/flows/。

这一件做完,第五节那张表里「会过期」的两行就变成「能」,毛病二和毛病四也一起没了。
我没有动任何代码,等你拍板。按你定的规矩(#161:代码改动先出 PR; 新功能先出设计再写),这一页就是设计。要往下走的话,我需要你在三件事里挑:

甲、只补采集 —— 侦查跑完自动跑 harvest_flow,落 dossier/flows/。 改动最小,解决「数据会过期」这一条。
乙、甲 + 一页回放 —— 再加一个入口,把本页这张表对任意一个 run 生成出来。 每篇跑完能自己看一眼。
丙、甲 + 乙 + 落盘边界 —— 顺带定义「哪些产物必须入库」, 让毛病四不会再发生第二次。

另外毛病一(「実」)是个当场就能修的小口子,一行词表的事, 但它属于代码改动,同样等你点头再开 PR。
