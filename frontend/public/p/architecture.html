5. 架构决策记录

ADR-1 阈值不跨平台复用,每个上游一个适配器

知乎问题的量纲是浏览 / 回答数 / 首答赞数;微博热搜是热度值 + 榜位;X 是 post 数 + 榜位。 「我还能不能排进去」只在知乎的答案排序下成立,别的平台没有对应物。 强行复用不是复用,是让上游模型泄漏进核心域。

实测背书:拿知乎热榜前三名过四道门槛,0 题合格,全部卡在回答数 (349 / 110 / 108,门槛 ≤50)。能上热榜的题按定义已经很挤,而门槛筛的恰恰是 「有流量但还没饱和」—— 两者天然互斥。所以热榜只能当事件线索,不能当答题候选池。

ADR-2 约束施加于出口,而非读模型

防编造的直觉做法是限制作者可见范围。这里反过来:成稿上下文对 raw/ 有完全读权限。 削减视野会同时削掉发现能力 —— 最锋利的观察产生于全部材料同处一个上下文之时。 代价原本由出口的闸门承担;闸门停用后,这个代价目前没有人承担。

ADR-3 分权靠确定性工具,不靠角色

此前是四个 LLM 角色 + can_use_tool 白名单。角色白名单约束的是 谁能调什么,而实际需要约束的是什么能通过。14 次选题破例 5 次、 5 次全部零产出,门槛入码之后该类越界不再可能 —— 直到门槛被停用为止。

ADR-4 浏览器通道唯一化

osascript 驱动已删。两条通道会争抢同一活动标签(症状:输入不生效、 JS 打到无关页面),且 osascript 的 TCC 授权会被静默撤销、失效时不报错。 现在传输层交给 Claude in Chrome,scout / hotlist 退化为「吐 JS + 归一化」的纯函数式工具。

ADR-5 语言消歧:一个词只在一个上下文里有意义

「闸门」曾同时指选题阈值、发稿规格、人工确认页三件事。 这不是措辞问题 —— 一次任务指令写着「取消闸门机制」,因为指代不清, 不得不停下来反问是哪一个。现在:selection 说门槛,quality 说闸门, review 说确认。Fowler:语言变了就需要另一个模型。
